# AGENTS.md

Anki flashcard app for PocketBook e-readers: Rust frontends over Anki's `rslib` backend, Slint software-rendered UI.

## Layout

A Cargo **workspace** (root `Cargo.toml`, one `Cargo.lock`, one `target/`). Shared dependency versions (anki, Slint, InkView, tokio) and the release profile live in `[workspace.dependencies]`/`[profile.*]` of the root manifest; members add features. `default-members` is core + desktop, so a plain `cargo build`/`cargo test`/`cargo run` covers the core tests and the desktop binary and never builds the InkView crate, and the ARM build always passes `-p pbanki`, so winit features never unify into it.
- `crates/core/` — package `pbanki-core`, the shared library. Owns the Slint build (`build.rs` compiles `ui/main.slint`; `lib.rs` does `slint::include_modules!()`).
  - `app.rs` — startup shared by both frontends: `app::start(config, native_keyboard, hooks) -> App` (collection, font registration, font probe, window, `init_ui`, `wire_callbacks`); `App::run` starts the auto-sync and the event loop.
  - `session.rs` — `LearnSession`, `init_session` (open, `.apkg` import, IO suspend), `reopen_collection`, `reset_session_memory`.
  - `study.rs` — worker-safe card loading and rating (`LoadedCard`, `next_card`, `rate_card`); `text.rs` — HTML stripping and pagination.
  - `sync/` — `mod.rs` (`sync_now`, `full_sync`, media sync), `client.rs` (`SyncManager`, anki HTTP calls), `auth.rs` (host key/login, endpoint parsing), `backup.rs` (pre-download backup).
  - `frontend/` — Slint wiring: `mod.rs` (`FrontendHooks`, `init_ui`, `wire_callbacks`), `card_jobs.rs` (worker jobs, delivery), `study.rs` (deck entry, rating, Home), `settings.rs`, `sync.rs` (`SyncHooks`, sync scheduling), `models.rs` (view models and `SyncState` constructors).
  - `config.rs`, `fonts.rs` (font catalog, Slint font registration, cmap coverage), `profile.rs` (opt-in timing).
  - `ui/` — Slint sources (not a crate).
- `crates/pocketbook/` — package `pbanki`, binary `pbanki`, PocketBook frontend via `inkview-rs`: `src/main.rs` (platform, hooks), `src/network.rs` (Wi-Fi), `src/keyboard.rs` (generic `OpenKeyboardEx` wrapper; the settings field mapping is in `main.rs`).
- `crates/desktop/` — package `pbanki-desktop`, winit desktop frontend for development.

Both frontends start through `pbanki_core::app::start` and only add platform pieces (PocketBook: Slint platform, Wi-Fi hooks, full-present hook, native keyboard). Card loading is dispatched to a worker thread from `crates/core/src/frontend/card_jobs.rs`; keep UI callbacks non-blocking. Shared behaviour belongs in `pbanki-core`; frontend `main.rs` files should stay platform-only.

## Commands

- Desktop dev run: `cd crates/desktop && cargo run` (paths are relative to the working directory: collection at `./pbanki/collection/`, config at `./pbanki/config.toml`; a config holding the device collection path is remapped to `./pbanki/collection` in `crates/desktop/src/main.rs`).
- PocketBook build: `make` (dev) / `make release` / `make release-profile` (adds the `profile` feature); runs `cargo zigbuild --target armv7-unknown-linux-gnueabi.2.23 -p pbanki --features=sdk-6-8`. Requires `cargo-zigbuild` + `zig` (provided by `shell.nix`).
- Emulator (PB700, external QEMU firmware emulator): `make emulator-dev` is the one-command interactive flow (setup + build + visible window + wizard + Wi-Fi + upload + deck + launch pbAnki). Individual steps: `make emulator-setup`, `make emulator-run`, `make emulator-build`, `make emulator-sync`, `make emulator-deck`. See `scripts/emulator/` and README. First setup downloads ~453 MiB firmware and builds patched QEMU; `make emulator-toolchain` installs Zig/cargo-zigbuild/Rust 1.99.1 target under `~/.local`/`~/.cargo`.
- `PBANKI_CONFIG` overrides the config path in `crates/pocketbook/src/main.rs` (used for host-side testing); default stays `/mnt/ext1/applications/pbanki/config.toml`.
- Toolchain is pinned to `1.99.1` in `rust-toolchain.toml`, which lists the required components (`rust-src`, `clippy`, `rustfmt`, `rust-analyzer`) and the armv7 target, so rustup installs them on first use. The pin tracks anki `main`, which pins `1.99.0` (the previous `1.89.0` pin and its "newer versions may fail clippy" comment were copied from anki's file). Bump it together with anki updates rather than independently, keep `cargo update` out of the same change, and re-run `make release` (zig link, glibc ≤ 2.23 via `readelf -V`) plus the PB710 timing baselines after a bump. Slint 1.17+ needs Rust ≥ 1.92.
- If `make` cannot find `zig`, add `~/.local/opt/zig-x86_64-linux-0.14.1` and `~/.local/bin` to `PATH` (see `scripts/emulator/install-toolchain.sh`). `rustc`/`cargo` must resolve to a rustup proxy (pacman `rustup` puts them in `/usr/bin`; the rustup-init install uses `~/.cargo/bin`, which `install-toolchain.sh` does not add to `PATH`). A distro `rust`/`cargo` package ignores `rust-toolchain.toml` and has no armv7 std, so ARM builds fail with `can't find crate for core`. Check with `rustc --print sysroot` (must be under `~/.rustup/toolchains/1.99.1-...`).
- `make release` stages a PocketBook bundle in `target/pocketbook/`: `pbanki.app` is a shell launcher and `pbanki.bin` is the ARM binary. The launcher sets `GLIBC_TUNABLES=glibc.rtld.execstack=2` for firmware 6.11.1480+ (same workaround as KOReader), keeps a single instance via `/tmp/pbanki.pid` (focusing it with `iv2sh SetActiveTask`), creates `pbanki/logs/` and rotates `pbanki/logs/pbanki.log` at launch when it exceeds 1 MiB, and logs start/exit status. Copy both files to `/mnt/ext1/applications/`; do not copy the raw binary as `pbanki.app`.
- Close pbAnki before replacing `pbanki.bin`: `/mnt/ext1` is FAT, and overwriting a running executable can terminate it with `SIGBUS`. Launching while it is already open only focuses the existing instance; package imports and config changes need a real restart.
- No lint config or CI exists. Unit tests are inline `#[cfg(test)] mod tests` at the end of the module they test: config, font-name (compares the header-only `name` reader with a full parse of every font under `/usr/share/fonts`), rating (`study.rs`, builds a throwaway collection in the temp dir), and sync-hook (`frontend/sync.rs`) tests in `pbanki-core` (`cargo test -p pbanki-core`); Wi-Fi ownership and keyboard truncation tests in `pbanki` (`cargo test -p pbanki --features sdk-6-8`). Clippy: `cargo clippy -p pbanki-core -p pbanki-desktop --all-targets` and `cargo clippy -p pbanki --features sdk-6-8`; core has pre-existing warnings (collapsible `if`, `CardState` clones).

## Device access

- Do not mount, read, write, or otherwise access the user's PocketBook (for example `/run/media/uu02d/PB710` or `/mnt/ext1`) unless the user explicitly asks. The user deploys builds and collects `pbanki/logs/pbanki.log` manually and will share logs when needed.

## InkView notes

### E-ink refresh

- **Backend:** `inkview-slint` from the fork `tl27863/inkview-rs`, branch `pbanki-upstream-master`: upstream master `15cdb98` (Sep 2026: generic pixel type, `EventLoopProxy`, `GetCanvas()` fallback, `PANEL_NO_FB_OFFSET`, SDK 6.11 bindings) plus pbanki commits `a2beb6c` (pixel formats, `copy_rect`, wake) and `6765a59` (presenter, damage policy, proxy, Slint 1.18.1). pbanki uses `sdk-6-8` with default features off (upstream defaults to `sdk-6-11`). The previous branch `pbanki-eink-refresh` (upstream `34ae238` + Slint `44208ff`) is kept unchanged as the rollback target. Upstream's own backend has no presenter or finalizer and can leave a loaded card or the loading screen invisible on PB710; use the fork.
- **Content updates** (answer reveal, rating → next card, pagination) use the damage path: `PartialUpdate` of the damage bounding box when the panel is idle; while it is busy, `DynamicUpdate` for accumulated damage up to 100k px, and a finalizer that issues one `PartialUpdate` of the union once the panel is idle. No full-frame re-blit and no `WaitForUpdateComplete`. `FullUpdate` (flashing) is only the finalizer's stuck-panel fallback after ~2 s; there is no periodic full refresh.
- **Full presents** (screen transitions and task show/resume) re-blit the retained frame and issue a non-flashing full-screen `PartialUpdate`. A `Presenter` state machine (`Idle | Pending | Verifying`) owns them: requests from `Show`/`Foreground`/`Repaint` and from `inkview_slint::request_full_present()` coalesce (queued events are drained before rendering, so Show+Foreground is one present); the present waits for the panel to be idle for at most 1.2 s, then issues anyway; one verification present follows 300 ms after issue. The app requests presents through `FrontendHooks.full_present` (set by `crates/pocketbook/src/main.rs`; desktop leaves it unset) for deck entry (loading screen if shown, and the first card), Home, and Settings open/back including automatic Settings opening. `PendingJob.full_transition` distinguishes deck entry from rating jobs. The request is an atomic latch consumed after event dispatch and before rendering, so the present contains the new screen.
- **Why the present design looks like this** (each was a device regression):
  - A frame drawn while InkView is switching tasks can be discarded, and `Foreground` alone creates no Slint damage, so the screen stayed blank until a touch. Show/resume must re-present the retained frame and verify it.
  - Slint dirties the whole window (1264×1680) for answer and next-card changes, so damage area cannot tell a screen replacement from a content change. Area thresholds made every rating a full present (1–1.5 s lag); keep transitions explicit.
  - `WaitForUpdateComplete` on content updates blocked the UI thread for 3–4 s per Show Answer.
  - Verification must be scheduled from issue time, not request time; a long first render otherwise swallowed it.
  - Every pressed/hover/animated style on a study control is an extra panel update that delays the following full-screen update by 0.5–0.8 s. Show Answer (`PlainButton`) and `RatingButton` have no pressed, hover, or animated styles; keep it that way.
- **Cross-thread wake:** all InkView screen calls run on the `pbanki-ui` thread while `InkViewMain` runs on the main thread. On the PB710 an update could be accepted but not carried out (panel reported idle ~100 ms later, nothing drawn) until the next touch woke the main loop. After every update call the backend runs `Screen::wake_event_loop()`, which posts a no-op `EVT_CUSTOM` to its own task with `SendEventTo` (unmapped by `Event::from_raw`, so never forwarded); this removed the stall. If it ever returns, use the single-threaded pump below.
- **Single-threaded InkView pump (designed, not implemented):** the structural fix for the cross-thread hazard, kept as the fallback if update stalls return or the wake stops working on new firmware.
  - `inkview`: add safe wrappers `prepare_for_loop(iv, handler)` and `process_event_loop_quick(iv)` (`PrepareForLoop`/`ProcessEventLoopQuick` already exist in `bindings_6_8.rs`), with the same handler-forwarding as `iv_main`.
  - `inkview-slint`: `Backend::run_event_loop` calls `ProcessEventLoopQuick()` every iteration, sleeping at most 20–50 ms while idle (instead of blocking in `recv_timeout`), and reads events the handler queued on the same thread. The `Presenter`, damage path, and logs stay as they are; `wake_event_loop()` becomes unnecessary.
  - `crates/pocketbook/src/main.rs`: drop the `pbanki-ui` thread and `iv_main`; call `prepare_for_loop` and run Slint on the main thread, so every InkView call happens on one thread.
  - Risks to check on device: `keyboard::open` (`OpenKeyboardEx`, callback-based) and `network::ensure_connected` (`NetConnect(NULL)` dialog) currently run on the UI thread while `InkViewMain` services them on the main thread; both must still work with the pump, and the blocking sync on the UI thread then also stops InkView event processing for its duration. Ship it as a separate build and repeat the launch/resume and study-flow device tests against the current backend.
- **Rendering:** `crates/pocketbook/src/main.rs` opens the framebuffer with `WhichScreen::new` (8-bit depth → `BB8`, 24-bit → `RGB24`, other depths panic) and boxes `Backend<P>` for that pixel type. Slint renders into a buffer in the framebuffer's own format (`Pixel<P>`), and damage and blits are copied row by row with `Screen::copy_rect` (5–9 ms for a full gray screen). Colour → gray uses integer Rec. 709 luma (neutral grays unchanged). The colour path has unit tests only: no colour device has been tested, and framebuffer byte order (assumed RGB) is unverified. The scale factor is `dpi / 100` from InkView (3.0 on the PB710, which the UI was laid out for), falling back to 3.0 outside [1.5, 6]. InkView's screen scale factor is deliberately ignored: it is the firmware UI zoom (1.16 on the PB710) and made the layout 16% larger (3.48). `Screen::new` sets `PANEL_NO_FB_OFFSET` (upstream fix for apps drawn below the status bar). InkView events reach the backend as `inkview_slint::Event::InkviewEvent`; `invoke_from_event_loop` callbacks arrive on the same channel and run in queue order before timers and the full-present latch. `update_timers_and_animations()` runs after event dispatch so Slint `changed` callbacks queued by input render in the same iteration. `inkview::screen::Screen` also exposes `full_update()`, `fast_update()` (`SoftUpdate`), `partial_update()`, `dynamic_update()`, `is_updating()`, and `wait_for_update_complete()`.
- **Logs** (`[eink +<ms>]`, timestamped from backend start): the backend header (size, bytes per pixel, scale factor, dpi, screen scale) after the `[inkview] framebuffer WxH depth=… stride=… dpi=… scale=…` line, `request reason=…` (`coalesced into …` when merged), `issued reason=… after=… waited=… attempts=… busy=… blit=…`, `verify issued …`, `panel busy→idle after …ms` (sampled every 50 ms while busy), `first full frame rendered in …ms`, `slow render: …`, one line per content update (`update partial|dynamic|finalize WxH+X+Y`, `damage … deferred to finalize (panel busy)`, `damage … held for pending present`), `pointer down|up x,y`, `key down …`, `waking InkView loop after updates … rc=…` once, and the rare `finalize fallback: FullUpdate`. `evt:` lines (including `PointerMove`) only with `INKVIEW_SLINT_TRACE_EVENTS`. Content updates must not log `request reason=App`. A dropped update shows as a full-screen `update …` followed by `panel busy→idle` within ~100 ms and nothing drawn until the next `pointer down`.
- **PB710 baselines** (`make release`, Oct 2026): first frame 300–500 ms after backend start; a full-screen `PartialUpdate` keeps the panel busy 550–650 ms (that is the floor for an answer or next card; going lower means smaller damage or `DynamicUpdate` for card changes, a ghosting/quality tradeoff to evaluate on-device); card jobs 10–30 ms, first deck entry ~200 ms (~135 ms of it `set_current_deck`); `answer_card` ~140 ms (FAT I/O; do not weaken SQLite durability to hide it); with the old Slint pin, fontdue first-use parse (vendored lazy patch): Ryo 48 ms, Adobe Ming 126 ms, Adobe Heiti 177 ms, Noto CJK 249 ms, and the UI family `Monospace` resolved to Roboto. These are not yet re-measured for Slint 1.18 (swash rasterization, fontconfig via dlopen).
- **Known minor issues:** rating taps produce empty damage (`update dynamic 0x0+0+0`, later `update finalize 0x0+0+0`), so the backend issues zero-area InkView updates; harmless but could be skipped. The `[job N]` worker/delivery lines are always on (two per card job).
- KOReader reference: `ffi/framebuffer_pocketbook.lua` maps partial to `PartialUpdate`/`PartialUpdateHQ`, full to `FullUpdate`/`FullUpdateHQ`, fast to `DynamicUpdate`, and waits with `WaitForUpdateComplete`; `ui/uimanager.lua` promotes every 6th partial refresh to a full refresh (`FULL_REFRESH_COUNT`, default 6).
- Upstream (`simmsb/inkview-rs`, remote `upstream` in `../inkview-rs`) still has no full-refresh policy or `Show`/`Repaint` handling. To follow a newer upstream master, rebase `pbanki-upstream-master` and keep the Slint version in the fork and all three pbanki manifests identical (two Slint copies fail to compile at `set_platform`).
- **Profiling** is opt-in via the `profile` cargo feature (`pbanki-core`, forwarded by the `pbanki` and `pbanki-desktop` manifests; `make release-profile`, `cd crates/desktop && cargo run --features profile`). Without it, `profile_log!` and `ProfileTimer` (`crates/core/src/profile.rs`) compile to nothing and release binaries contain no `[profile]` strings. With it, `crates/core/src/study.rs` splits card loading into deck selection, queue, state descriptions, render, text processing, font choice, pagination, and answer write; `crates/core/src/fonts.rs` logs catalog, coverage, and registration timings; `app::start` logs startup; and `spawn_font_probe` logs the read time and size of each registered card font (Slint reads them fully at startup) and which font `Monospace` resolves to in Slint's shared collection, queried in Slint's order (named family, sans-serif, system-ui) (`[profile] font '…' … read=… bytes=…`, `[profile] UI family '…' resolves to …`), starting 10 s after launch at nice 19. Logs go to the eMMC-backed `pbanki.log`, so timings include logging overhead.

### Wi-Fi and sync

- `crates/pocketbook/src/network.rs` owns Wi-Fi. `ensure_connected()` checks `QueryNetwork() & NET_CONNECTED`; otherwise it powers the radio with `WiFiPower(1)` and uses the system `NetConnect(NULL)` dialog. `NetConnectSilent` is not used: on PB710 a cold radio can block for over a minute, and calling it off-thread can return `NET_ABORTED`. The dialog lets the user enable/select Wi-Fi without leaving the app. Failures map to actionable messages instead of opening the in-app sync settings.
- `disconnect_after_sync()` only disconnects connections the app established. It captures the active SSID with `NetInfo()` after connecting and skips `NetDisconnect()` if the current SSID changed, so a network the user switched to mid-sync is left connected.
- `pbanki_core::frontend` exposes `FrontendHooks { sync: SyncHooks, full_present }`, passed to `app::start`. `SyncHooks { before_sync, after_sync }` is invoked for every sync path (manual, full upload/download, startup auto-sync, sync-on-exit). `before_sync` runs on the UI thread and must be cheap and idempotent; it may show a platform prompt (for example Wi-Fi setup) but must not block indefinitely on its own. A failure sets a `SyncState` error and skips the sync. `after_sync` runs exactly once iff `before_sync` returned `Ok`, including when the sync fails or panics, and never runs after a pre-sync failure. Desktop passes no-op hooks.
- If Wi-Fi was already connected before sync, the app leaves it connected; only connections started by the app are disconnected afterward.
- InkView also exposes `NetConnect` (interactive dialog), `NetConnect2`, `NetConnectAsync`, `NetConnect3` (6.8+), `GetNetState`, `GetLastNetConnectionError`, `NetInfo`, `EnumWirelessNetworks`, and `NetMgrPing`. `EVT_NET_CONNECTED`/`EVT_NET_DISCONNECTED` are not surfaced by `inkview::Event`, so status would need polling.

## Gotchas

- `anki`/`anki_proto` come from `ankitects/anki` `branch = "main"` (git dep, unpinned); `slint`/`slint-build` are `1.18.1` from crates.io. The single workspace `Cargo.lock` pins the anki revision for both frontends; do not `cargo update` it together with other changes.
- **Slint 1.18 fonts.** Slint 1.16+ rasterizes glyphs with swash (lazy per glyph) instead of fontdue, so the old vendored fontdue patch (eager outlining took 5.5 s for Ryo Gothic and 16 s for Adobe Ming on the PB710) was removed; if a future Slint brings fontdue back, re-check first-render time. fontique 0.11 links fontconfig on Linux; the root manifest enables `fontique/fontconfig-dlopen` so the armv7 cross build needs no fontconfig sysroot, and without `libfontconfig.so.1` on the device system fonts are skipped (registered card fonts still work, and become the UI fallback). The PB710 has it: `Monospace` resolves to Roboto.
- **Glyph embedding.** `crates/core/build.rs` uses `EmbedForSoftwareRenderer`, which pre-rasterizes every literal font size in the UI (plus the SVG icons, which need it: runtime SVG decoding is not enabled). A constant `0px` size, such as an unset std-widgets `CheckBox` `font-size`, is rasterized at the font's design size: 380 MB of generated code and an 80 MB binary. `crates/core/ui/screens/settings.slint` therefore sets the CheckBoxes to `12px` (Slint's default). After UI changes, check that `target/*/build/pbanki-core-*/out/main.rs` stays around 3 MB and has no `pixel_size : 0`. The embedded bitmap font is whatever default sans the build host has (Noto Sans here), with only ASCII plus characters from `.slint` literals. With `systemfonts`, Slint uses a bitmap font only when a text's requested family matches its name exactly, or as the last fallback when the requested family resolves to nothing or no family is requested. `MainWindow` therefore sets `default-font-family: Constants.font_family_standard`, so std-widgets labels (CheckBox, Button) also use the runtime UI font and render any translated characters; this replaced a `dummy` string property that only padded the bitmap font with Latin-1 glyphs.
- Root `Cargo.toml` uses the fork's git branch `pbanki-upstream-master` for InkView. Keep that branch pushed; pin a specific rev if reproducibility matters. Fork development still uses the local checkout `../inkview-rs`. The user permits committing and pushing InkView changes to the fork's pbanki branches as part of normal work.
- Slint's version and base software-renderer features are set once in the root `[workspace.dependencies]`; members only add features (`unstable-fontique-011` in core, `backend-winit` in desktop). `crates/core/build.rs` embeds resources `EmbedForSoftwareRenderer`.
- PocketBook fonts: USB/mass-storage view shows `/system/fonts` and `/system/adobe/fonts`, but on-device the runtime paths are `/mnt/ext1/system/fonts` and `/mnt/ext1/system/adobe/fonts`. PB700 images use `/fonts` and `/adobefonts` (not `/ebrmain/fonts`). `/mnt/ext1/system/adobe/fonts/RyoGothicPlusN-Medium.otf` (2.3 MB, typographic family `Ryo Gothic PlusN`) covers Japanese and is the card default; `/mnt/ext1/system/fonts/NotoSansCJK-Regular.ttc` is a 19 MB CFF collection, and `fireflysung.ttf` lacks `両`. `crates/core/src/fonts.rs` builds a catalog from `Config.general.font_dirs` (reading only each file's sfnt/TTC table directory and `name` table, not the whole file), registers the primary/fallback files with Slint via `crates/core/src/fonts.rs::register_catalog_fonts` (called by `app::start` before `MainWindow::new`; the files are memory-mapped into Slint's shared fontique collection via `slint::fontique_011::shared_collection()` (feature `unstable-fontique-011` in `crates/core/Cargo.toml`; needs the Slint platform, so call it after `set_platform`), ordered by configured family and put first in the Hira/Kana/Hani/Hang fallback chains. Do not use `SLINT_FONT_PATH`/`SLINT_DEFAULT_FONT`: in Slint 1.18 they make the registered fonts the generic sans-serif chain, and the UI family `Monospace` (not a real family, so it falls back to sans-serif) then rendered in Ryo Gothic instead of Roboto), and checks card text against each font's cmap. `next_card` picks the first font that covers the whole card; if none does, it replaces the missing glyphs with `?` instead of rendering missing glyphs. Card text uses `Config.general.card_font` plus `card_fallback_fonts`; the UI stays `Monospace` (Roboto on the PB710).
- `Config` stores its loaded path in the serde-skipped `path` field; `save()` writes there. `[ankiweb].endpoint` is blank for AnkiWeb, and `sync_media` defaults to true. `[general]` has `card_font` (default `Ryo Gothic PlusN`), `card_fallback_fonts` (`Adobe Ming Std`, `Adobe Heiti Std`, `Noto Sans CJK JP`), and `font_dirs` (PB710 runtime, USB, and PB700 paths). `load_or_create` adds any missing font keys to an existing config and saves it; the generated template contains all three.
- **Card loads run off the UI thread.** `next_card`/`rate_card` in `crates/core/src/study.rs` are collection-only functions returning `LoadedCard`; `crates/core/src/frontend/card_jobs.rs` takes the collection out of `LearnSession`, runs the job on a `std::thread`, and puts it back when the result arrives. While a job or sync is active, `LearnSession.busy` is true and `MainWindow.busy` mirrors it, so Home and deck-selection navigation are ignored until the collection is available again; `LearnScreen.busy` disables Show Answer, the rating buttons, and study keys so taps aimed at the next card are not swallowed by the previous card's controls. The UI also shows a loading state (`MainWindow.loading` / `loading_message`). Do not touch the collection from UI callbacks without checking `busy`.
- Deck loads show the loading screen only if the job is still running after 200 ms (`Loading::Transition(DECK_LOADING_DELAY)`), so fast loads present the card with a single full present instead of loading screen + card. The deck list stays visible until then: `MainWindow.learning` is set from Rust (loading timer, `finish_job`, or the collection-unavailable error) rather than in `ui/main.slint`, so `LearnScreen` never renders the previous session's card. Because `LearnScreen` is then created while the window layout is being evaluated, it takes key focus from a one-shot `Timer`, not `init => { self.focus(); }`, which re-entered the geometry binding and aborted with Slint's "Recursion detected"; do not move focus calls back into `init` of conditionally created screens; `on_open_settings` ignores taps while busy because the gear stays reachable during that window. Rating loads defer it by 300 ms (`Loading::Deferred(RATING_LOADING_DELAY)`) so the `RatingButton` that received the click is not removed inside its own click callback, and the rating handlers do not change `show_answer`; the answer stays visible until the deferred loading overlay or the next card (`changed card` resets it). Finishing a job bumps `job_seq` so its deferred overlay timer cannot fire during a later sync or job.
- Background card jobs deliver results with `slint::invoke_from_event_loop` (both backends implement the event loop proxy): `spawn_card_job` stores the single in-flight job in the thread-local `PENDING_JOB`, and the worker's `DeliverOnDrop` guard schedules `deliver_job`, also when the job panics (its sender is dropped first, so delivery sees the result or a disconnected channel). Card-job loading and result transitions call `request_redraw()` explicitly so the backend presents their damage without waiting for further input. Slint timers only fire because the backend drives `duration_until_next_timer_update`. The proxy also makes it possible to move the blocking sync off the UI thread later.
- **Re-test redraws after InkView/Slint upgrades.** On PB710, implicit property invalidation alone could leave a loading screen or already-delivered card invisible until another touch, even when the worker finished in milliseconds. The explicit `request_redraw()` calls in `spawn_card_job`, its deferred loading timer, and `finish_job` are intentional. Before removing them after an upgrade, verify cold-launch deck selection, loading-to-card transitions, rating, and Home/re-entry without any extra touch. Device logs (`pbanki/logs/pbanki.log`, see the e-ink log notes) show whether a stale screen was never rendered, never issued, or dropped by the panel.
- `set_current_deck` (~135 ms on the PB710) is only called when the selected deck actually changes (`LearnSession.current_deck_id`), avoiding a transaction per card. The cache is cleared by `session::reset_session_memory` after every sync (a merge can pull another device's `curDeck` or delete the deck) and after a failed card load; deck entry logs `[deck <id>] entering, set_deck=<bool>`. A failed `answer_card` returns an error card instead of loading the unchanged queue head (test in `study.rs`). `start_time` is recorded when the card is displayed, so `milliseconds_taken` excludes load/render time.
- Sync now supports normal merge, full upload/download, and media sync in `crates/core/src/sync/`. Full sync and card loads both temporarily take the collection out of `LearnSession.collection` (an `Option`) and reopen/restore it; they share `LearnSession.busy`. Sync is still blocking on the UI thread; progress/abort is not implemented (the unused `SyncStatus` progress plumbing was removed; add progress back together with off-thread sync).
- Anki queue builds are much slower in the dev profile. Measure card-load latency with `make release`; `make` (dev) and `scripts/emulator/build-app.sh` use the dev profile.
- `sync_on_exit` means after leaving a study session (LearnScreen home), not on application exit.
- Sync settings live in `crates/core/ui/screens/settings.slint`; the home gear opens it and the reload icon triggers sync. Shared wiring lives in `crates/core/src/frontend/`; PocketBook adds the native InkView keyboard (`crates/pocketbook/src/keyboard.rs`, wired in `main.rs` by `EditField`) and desktop uses normal `LineEdit` input. The keyboard result is delivered with `slint::invoke_from_event_loop` (the callback runs on the InkView thread); a cancelled keyboard (NULL text) keeps the field unchanged. The buffer is 512 bytes including the NUL; longer initial values are truncated on a character boundary.
- `init_session` calls `with_desktop_media_paths()` so `collection.media/` and `collection.mdb` exist. Do not remove this or media sync will fail.
- On startup, `init_session` imports any unimported `*.apkg` in the collection directory (including scheduling/media) and renames it to `*.apkg.imported`. This is how users install decks on-device; see `import_pending_packages()` in `crates/core/src/session.rs`.
- `crates/core/src/session.rs` suspends "Image Occlusion Enhanced" cards at session init.
- `scripts/mount.sh` mounts the device over CIFS to `target/armv7-unknown-linux-gnueabi/debug/applications/`.
- Emulator checkout is external (`EINK_EMULATOR_DIR`, default `../eink-emulator`) and not vendored. `scripts/emulator/setup.sh` fixes the upstream QEMU submodule's SSH URL to HTTPS. `enable-wifi.py` uses the quick-settings Wi-Fi toggle and configures `PocketBook-QEMU` through `wpa_cli` over the serial console; do not navigate Settings > Wi-Fi (firmware versions put Wi-Fi on different rows). Sync also uses the serial console, not SSH. `sync-app.sh` uploads to a `.new` file and renames it so a running pbAnki keeps working. `install-deck.sh` replaces the emulator collection with `scripts/emulator/JLPT_N2_Grammar.apkg` unless the `.pbanki-deck` marker exists; it must run while pbAnki is stopped.
- The emulator runs the ARM binary directly as `pbanki.app`, so it does not exercise the release launcher (`scripts/pocketbook/pbanki.app`). Launcher changes need a device check unless the emulator packaging is changed to upload `pbanki.app` + `pbanki.bin`.
