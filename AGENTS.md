# AGENTS.md

Anki flashcard app for PocketBook e-readers: Rust frontends over Anki's `rslib` backend, Slint software-rendered UI.

## Layout

A Cargo **workspace** (root `Cargo.toml`, one `Cargo.lock`, one `target/`). Shared dependency versions (anki, Slint, InkView, tokio) and the release profile live in `[workspace.dependencies]`/`[profile.*]` of the root manifest; members add features. `default-members` is core + desktop, so a plain `cargo build`/`cargo test`/`cargo run` covers the core tests and the desktop binary and never builds the InkView crate, and the ARM build always passes `-p pbanki`, so winit features never unify into it.
- `crates/core/` — package `pbanki-core`, the shared library. Owns the Slint build (`build.rs` compiles `ui/main.slint`; `lib.rs` does `slint::include_modules!()`).
  - `app.rs` — startup shared by both frontends: `app::start(config, native_keyboard, hooks) -> App` (collection, font registration, font probe, window, `init_ui`, `wire_callbacks`); `App::run` starts the auto-sync and the event loop.
  - `session.rs` — `LearnSession`, `init_session` (open, `.apkg` import, IO suspend), `reopen_collection`, `reset_session_memory`.
  - `study.rs` — worker-safe card loading and rating (`LoadedCard`, `next_card`, `rate_card`); `text.rs` — HTML stripping and pagination.
  - `sync/` — `mod.rs` (`sync_now`, `full_sync`, media sync), `client.rs` (`SyncManager`, anki HTTP calls), `auth.rs` (host key/login, endpoint parsing), `backup.rs` (pre-download backup).
  - `frontend/` — Slint wiring: `mod.rs` (`FrontendHooks`, `init_ui`, `wire_callbacks`), `card_jobs.rs` (worker jobs, delivery), `study.rs` (deck entry, rating, Home), `settings.rs`, `sync.rs` (`SyncHooks`, sync scheduling), `models.rs` (view models and `SyncState` constructors).
  - `config.rs`, `fonts.rs` (font catalog, Slint font registration, cmap coverage), `profile.rs` (opt-in timing).
  - `ui/` — Slint sources (not a crate).
- `crates/pocketbook/` — package `pbanki`, binary `pbanki`, PocketBook frontend via `inkview-rs`: `src/main.rs` (platform, hooks, `[device]` log, panel/update-policy options), `src/network.rs` (Wi-Fi), `src/keyboard.rs` (generic `OpenKeyboardEx` wrapper; the settings field mapping is in `main.rs`). Features `sdk-6-10` (base, B288/B300) and `sdk-6-11` (RK3566); exactly one must be enabled.
- `crates/desktop/` — package `pbanki-desktop`, winit desktop frontend for development. Feature `eink-sim` (`src/eink_sim.rs`) instead runs the inkview-slint backend over a simulated e-ink panel in a `minifb` window.

Both frontends start through `pbanki_core::app::start` and only add platform pieces (PocketBook: Slint platform, Wi-Fi hooks, full-present hook, native keyboard). Card loading is dispatched to a worker thread from `crates/core/src/frontend/card_jobs.rs`; keep UI callbacks non-blocking. Shared behaviour belongs in `pbanki-core`; frontend `main.rs` files should stay platform-only.

## Commands

- Desktop dev run: `cd crates/desktop && cargo run` (paths are relative to the working directory: collection at `./pbanki/collection/`, config at `./pbanki/config.toml`; a config holding the device collection path is remapped to `./pbanki/collection` in `crates/desktop/src/main.rs`).
- PocketBook builds (firmware 6.10+ only; glibc floor 2.38, what the 6.10 and 6.11 `libinkview.so` need): base B288/B300 soft-float `make` (dev) / `make release` / `make release-profile` → `cargo zigbuild --target armv7-unknown-linux-gnueabi.2.38 -p pbanki --features=sdk-6-10`, bundle `target/pocketbook/`; RK3566 hard-float `make rk3566` / `make release-rk3566` / `make release-rk3566-profile` → `armv7-unknown-linux-gnueabihf.2.38 --features=sdk-6-11`, bundle `target/pocketbook-rk3566/`. Two bundles with identical file names; the user installs the one for the device. The PB710 is soft-float (base bundle). Requires `cargo-zigbuild` + `zig` 0.14.1 (`cargo install cargo-zigbuild --locked` and a Zig tarball, or `shell.nix`).
- SDK PC emulator (replaces the former QEMU PB700 emulator): `make sdk-emulator-setup [SDK=6.11]` once, then `make sdk-emulator [SDK=6.11]` (build + run). Runs the SDK's x86-64 InkView (GTK2 window) in Docker (`scripts/sdk-emulator/`, images `pbanki-sdk-emulator:<sdk>`: bookworm for 6.10, trixie for 6.11, matching the SDK libs' ICU/jsoncpp/glibc) with pbAnki built for `x86_64-unknown-linux-gnu.<2.34|2.38>`. SDK archives come from the Sean-on-Git re-upload, pinned in `scripts/sdk-emulator/SHA256SUMS`; only `local/lib` and `local/share/config` are extracted to `target/sdk/<sdk>/runtime/`, and the `system/` data tree comes from the same repo's git tree (commit `715cda6`). Defaults: 6.10 → hwconfig profile `700`, display mode 16 (1264×1680 @ 300 dpi); 6.11 → profile `1030` (RK3566), display mode 12 (1404×1872). See "SDK emulator" under Gotchas.
- Desktop e-ink simulation: `cd crates/desktop && cargo run --features eink-sim` (timings via `PBANKI_EINK_SIM_MS`).
- Waveform probe: `make waveform-probe` builds the inkview-rs `waveform_probe` example from `../inkview-rs` for the base ABI (`target/pocketbook-probe/waveform-probe.app`); on the device it writes `applications/waveform-probe.log`. In the emulator: `EMU_APP=<x86-64 build> make sdk-emulator`.
- `PBANKI_CONFIG` overrides the config path in `crates/pocketbook/src/main.rs` (used for host-side testing); default stays `/mnt/ext1/applications/pbanki/config.toml`.
- Toolchain is pinned to `1.99.1` in `rust-toolchain.toml`, which lists the required components (`rust-src`, `clippy`, `rustfmt`, `rust-analyzer`) and both armv7 targets (`gnueabi`, `gnueabihf`), so rustup installs them on first use. The pin tracks anki `main`, which pins `1.99.0` (the previous `1.89.0` pin and its "newer versions may fail clippy" comment were copied from anki's file). Bump it together with anki updates rather than independently, keep `cargo update` out of the same change, and re-run `make release` and `make release-rk3566` (zig link, glibc ≤ 2.38 via `readelf -V`, soft/hard-float via `readelf -h`) plus the PB710 timing baselines after a bump. Slint 1.17+ needs Rust ≥ 1.92.
- If `make` cannot find `zig`, add `~/.local/opt/zig-x86_64-linux-0.14.1` and `~/.local/bin` to `PATH`. `rustc`/`cargo` must resolve to a rustup proxy (pacman `rustup` puts them in `/usr/bin`; the rustup-init install uses `~/.cargo/bin`). A distro `rust`/`cargo` package ignores `rust-toolchain.toml` and has no armv7 std, so ARM builds fail with `can't find crate for core`. Check with `rustc --print sysroot` (must be under `~/.rustup/toolchains/1.99.1-...`).
- `make release` (or `make release-rk3566`) stages a PocketBook bundle in `target/pocketbook/` (`target/pocketbook-rk3566/`): `pbanki.app` is a shell launcher and `pbanki.bin` is the ARM binary. The launcher sets `GLIBC_TUNABLES=glibc.rtld.execstack=2` for firmware 6.11.1480+ (same workaround as KOReader), keeps a single instance via `/tmp/pbanki.pid` (focusing it with `iv2sh SetActiveTask`), creates `pbanki/logs/` and rotates `pbanki/logs/pbanki.log` at launch when it exceeds 1 MiB, and logs start/exit status; on exit code 126/127 it logs which bundle the device needs (`/lib/ld-linux-armhf.so.3` present = RK3566). Copy both files to `/mnt/ext1/applications/`; do not copy the raw binary as `pbanki.app`.
- Close pbAnki before replacing `pbanki.bin`: `/mnt/ext1` is FAT, and overwriting a running executable can terminate it with `SIGBUS`. Launching while it is already open only focuses the existing instance; package imports and config changes need a real restart.
- No CI exists. `make lint` runs clippy and the ast-grep rules (see "Lint rules (ast-grep)"). Unit tests are inline `#[cfg(test)] mod tests` at the end of the module they test: config, font-name (compares the header-only `name` reader with a full parse of every font under `/usr/share/fonts`), rating (`study.rs`, builds a throwaway collection in the temp dir), and sync-hook (`frontend/sync.rs`) tests in `pbanki-core` (`cargo test -p pbanki-core`); Wi-Fi ownership and keyboard truncation tests in `pbanki` (`cargo test -p pbanki --features sdk-6-10`); simulator tests in `pbanki-desktop` (`cargo test -p pbanki-desktop --features eink-sim`). In `../inkview-rs`: device/update-name tests (`cargo test -p inkview --no-default-features --features sdk-6-10 --lib`; its doctests fail on bindgen comments, pre-existing) and update-policy tests (`cargo test -p inkview-slint --no-default-features --features sdk-6-10`). Clippy: `cargo clippy -p pbanki-core -p pbanki-desktop --all-targets`, `-p pbanki-desktop --features eink-sim`, and `-p pbanki --features sdk-6-10` / `sdk-6-11`; core has pre-existing warnings (collapsible `if`, `CardState` clones).

## InkView notes

### E-ink refresh

- **Backend:** `inkview-slint` from the fork `tl27863/inkview-rs`, branch `pbanki-upstream-master`: upstream master `15cdb98` (Sep 2026: generic pixel type, `EventLoopProxy`, `GetCanvas()` fallback, `PANEL_NO_FB_OFFSET`, SDK 6.11 bindings) plus pbanki commits `a2beb6c` (pixel formats, `copy_rect`, wake) and `6765a59` (presenter, damage policy, proxy, Slint 1.18.1). Branch `pbanki-device-panel` (cut from `pbanki-upstream-master` at `3a651ab`) adds `inkview::device` (`DeviceInfo`), the update API (`UpdateKind`, `Waveform`, `UpdFlags`, `Screen::update`/`update_ex`/`waveform_times`/A2), `PanelMode` + panel calls, `Screen::copy_rect_from`, the `waveform_probe` example (re-execs itself with `GLIBC_TUNABLES=glibc.rtld.execstack=2` so it runs as a bare `.app` on 6.11.1480+, and logs panics to its log file), and in inkview-slint the `EinkScreen` trait (`Backend<S: EinkScreen>`), `UpdatePolicy`/`BackendOptions`, and the panel offset; `pbanki-upstream-master` is the rollback target for it. pbanki uses `sdk-6-10` (base) or `sdk-6-11` (RK3566) with default features off (upstream defaults to `sdk-6-11`); the bindings load symbols lazily (a missing symbol panics only when called), so new calls check `iv.X.as_ref().is_ok()` (`DeviceInfo::query` and `Screen::update` never panic on a missing symbol). The `sdk-5-19` feature no longer compiles (`EVT_CUSTOM`, pre-existing). The older branch `pbanki-eink-refresh` (upstream `34ae238` + Slint `44208ff`) is kept unchanged as the rollback target. Upstream's own backend has no presenter or finalizer and can leave a loaded card or the loading screen invisible on PB710; use the fork.
- **Content updates** (answer reveal, rating → next card, pagination) use the damage path: `PartialUpdate` of the damage bounding box when the panel is idle; while it is busy, `DynamicUpdate` for accumulated damage up to 100k px, and a finalizer that issues one `PartialUpdate` of the union once the panel is idle. No full-frame re-blit and no `WaitForUpdateComplete`. `FullUpdate` (flashing) is only the finalizer's stuck-panel fallback after ~2 s; there is no periodic full refresh.
- **Full presents** (screen transitions and task show/resume) re-blit the retained frame and issue a non-flashing full-screen `PartialUpdate`. A `Presenter` state machine (`Idle | Pending | Verifying`) owns them: requests from `Show`/`Foreground`/`Repaint` and from `inkview_slint::request_full_present()` coalesce (queued events are drained before rendering, so Show+Foreground is one present); the present waits for the panel to be idle for at most 1.2 s, then issues anyway; one verification present follows 300 ms after issue. The app requests presents through `FrontendHooks.full_present` (set by `crates/pocketbook/src/main.rs`; desktop leaves it unset) for deck entry (loading screen if shown, and the first card), Home, and Settings open/back including automatic Settings opening. `PendingJob.full_transition` distinguishes deck entry from rating jobs. The request is an atomic latch consumed after event dispatch and before rendering, so the present contains the new screen.
- **Why the present design looks like this** (each was a device regression):
  - A frame drawn while InkView is switching tasks can be discarded, and `Foreground` alone creates no Slint damage, so the screen stayed blank until a touch. Show/resume must re-present the retained frame and verify it.
  - Slint dirties the whole window (1264×1680) for answer and next-card changes, so damage area cannot tell a screen replacement from a content change. Area thresholds made every rating a full present (1–1.5 s lag); keep transitions explicit.
  - `WaitForUpdateComplete` on content updates blocked the UI thread for 3–4 s per Show Answer.
  - Verification must be scheduled from issue time, not request time; a long first render otherwise swallowed it.
  - Every pressed/hover/animated style on a study control is an extra panel update that delays the following full-screen update by 0.5–0.8 s. Show Answer (`PlainButton`) and `RatingButton` have no pressed, hover, or animated styles; keep it that way.
- **Cross-thread wake:** all InkView screen calls run on the `pbanki-ui` thread while `InkViewMain` runs on the main thread. On the PB710 an update could be accepted but not carried out (panel reported idle ~100 ms later, nothing drawn) until the next touch woke the main loop. After every update call the backend runs `Screen::wake_event_loop()`, which posts a no-op `EVT_CUSTOM` to its own task with `SendEventTo` (unmapped by `Event::from_raw`, so never forwarded); this removed the stall. If it ever returns, use the single-threaded pump below.
- **Single-threaded InkView pump (designed, not implemented):** the structural fix for the cross-thread hazard, kept as the fallback if update stalls return or the wake stops working on new firmware.
  - `inkview`: add safe wrappers `prepare_for_loop(iv, handler)` and `process_event_loop_quick(iv)` (`PrepareForLoop`/`ProcessEventLoopQuick` already exist in `bindings_6_8.rs`), with the same handler-forwarding as `iv_main`.
  - `inkview-slint`: `Backend::run_event_loop` calls `ProcessEventLoopQuick()` every iteration, sleeping at most 20–50 ms while idle (instead of blocking in `recv_timeout`), and reads events the handler queued on the same thread. The `Presenter`, damage path, and logs stay as they are; `wake_event_loop()` becomes unnecessary.
  - `crates/pocketbook/src/main.rs`: drop the `pbanki-ui` thread and `iv_main`; call `prepare_for_loop` and run Slint on the main thread, so every InkView call happens on one thread.
  - Risks to check on device: `keyboard::open` (`OpenKeyboardEx`, callback-based) and `network::ensure_connected` (`NetConnect(NULL)` dialog) currently run on the UI thread while `InkViewMain` services them on the main thread; both must still work with the pump, and the blocking sync on the UI thread then also stops InkView event processing for its duration. Ship it as a separate build and repeat the launch/resume and study-flow device tests against the current backend.
- **Rendering:** `crates/pocketbook/src/main.rs` opens the framebuffer with `WhichScreen::with_panel(iv, PanelMode)` (8-bit depth → `BB8`, 24-bit → `RGB24`, other depths panic) and boxes `Backend<Screen<P>>` via `Backend::with_options` for that pixel type. Slint renders into a buffer in the framebuffer's own format (`Pixel<P>`), and damage and blits are copied row by row with `Screen::copy_rect` (5–9 ms for a full gray screen). Colour → gray uses integer Rec. 709 luma (neutral grays unchanged). The colour path has unit tests only: no colour device has been tested, and framebuffer byte order (assumed RGB) is unverified. The scale factor is `dpi / 100` from InkView (3.0 on the PB710, which the UI was laid out for), falling back to 3.0 outside [1.5, 6]. InkView's screen scale factor is deliberately ignored: it is the firmware UI zoom (1.16 on the PB710) and made the layout 16% larger (3.48). `PanelMode::Hidden` (default) sets `PANEL_NO_FB_OFFSET` only (upstream fix for apps drawn below the status bar). InkView events reach the backend as `inkview_slint::Event::InkviewEvent`; `invoke_from_event_loop` callbacks arrive on the same channel and run in queue order before timers and the full-present latch. `update_timers_and_animations()` runs after event dispatch so Slint `changed` callbacks queued by input render in the same iteration. `inkview::screen::Screen` also exposes `full_update()`, `fast_update()` (`SoftUpdate`), `partial_update()`, `dynamic_update()`, `is_updating()`, and `wait_for_update_complete()`.
- **Update policy:** every update the backend issues goes through `UpdatePolicy` (`inkview-slint/src/policy.rs`): `idle_content` (default `partial`), `busy_content` (`dynamic`), `finalize` (`partial`), `present` (`partial`; `partial-hq` when `DeviceInfo` reports a colour mask, via `UpdatePolicy::for_panel`), `fallback` (`full`). The defaults reproduce the tuned PB710 behaviour; do not change them without PB710 measurements. `INKVIEW_SLINT_UPDATES="busy_content=dynamic-bw,present=ex:gl16"` overrides classes for device experiments (values: `UpdateKind` names or `ex:<waveform>`; `ex:` uses `UpdateEx`, SDK 6.10+, falling back to `partial`). That `UpdateEx`'s low flag bits select a `waveform_type_t` is unverified: run the waveform probe on the PB710 and compare its `ex:` busy times with `GetWaveformTimes`. Zero-area damage issues no update. Not exposed on purpose: `device_epdc_init()->update` (bypasses InkView). Recommended experiments once the probe confirms `UpdateEx`: `busy_content=dynamic-bw`, then `present=ex:gl16` vs `partial` for card changes (latency vs ghosting); record results in the baselines below.
- **Device info:** `inkview::device::DeviceInfo::query(iv)` (after `Init`; hwconfig is loaded by InkView's init, earlier calls read zeros) gives model/hardware/firmware strings and the hwconfig IDs (device, platform, display geometry, colour mask, EPDC, peripherals); unknown IDs keep their raw value. The PB710's device ID (49) is not in any public header; it was added to the table from a device log (fw U710.6.11.2124). pbanki logs it as `[device] …` and warns when hwconfig DPI ≠ `get_screen_dpi()`. The serial number and device key are deliberately not read.
- **System panel (on by default):** `[general] system_panel = true` (default since Nov 2026; `false` → `PanelMode::Hidden`; configs written earlier already hold `false` and keep it) → `PanelMode::System`: `SetPanelType(PANEL_ENABLED | PANEL_NO_FB_OFFSET)` + `InitPanel()` + `SetShowPanelReader(1)`. The last call is required: the task sets `APPLICATION_READER`, and InkView gives reader apps a panel only when `show_status_bar` in `global.cfg` (the reader status bar setting, loaded by `InitPanel`, default 1) is on; with it 0, `is_panel_active()` is false and `PanelHeight()` returns 0 (the PB710 had it off; reproduce in the emulator by adding `show_status_bar=0` to `target/sdk-emulator/<sdk>/work/system/config/global.cfg`). `SetShowPanelReader` sets InkView's in-memory flag for this task only and does not save the setting. The backend reserves `Screen::panel_height()` rows at the top (Slint window and retained buffer are `width × (height - top)`, all copies and update rects are shifted by `top`), the full present blits only the content rows and calls `DrawPanel(NULL, NULL, NULL, -1)` before its full-screen update, pointer presses with `y < top` are not forwarded (InkView handles the panel and its tray itself; in the emulator such taps never reach the app), and `Show`/`Repaint` re-read the height (resize + full render on change). `PanelHeight()` reports a height even when the panel is hidden (any panel flag counts as active), so `Screen` remembers its `PanelMode` and reports 0 when hidden. The panel redraws itself on InkView's timer (clock/battery); if logs show those updates colliding with presents, switch to `SetManualPanelUpdates(1, handler)` and feed its rects into the damage path. The height is whatever `PanelHeight()` reports (it follows the theme and screen: 76 px in the SDK emulator, 123 px on the PB710); `Screen::panel_height()` only rejects values ≤ 0 or ≥ the screen height. Verified in the SDK emulator (bar drawn, taps offset correctly, also with `show_status_bar=0`); the tray opens on the PB710 (`control_panel_mgr.app`; the emulator has none) and the app re-presents on return (`request reason=Foreground`).
- **Logs** (`[eink +<ms>]`, timestamped from backend start): `[device] …` first, then the backend header (size, bytes per pixel, scale factor, dpi, screen scale), `update policy: …`, `waveform times (ms, by waveform id): […]`, and `panel mode=system height=… (raw …) fb_offset=… show_reader=…` (whenever the panel is enabled; `height=0` means `PanelHeight()` returned 0 or more than a quarter of the screen, so no rows were reserved; no line at all means `PanelMode::Hidden`) after the `[inkview] framebuffer WxH depth=… stride=… dpi=… scale=…` line, `request reason=…` (`coalesced into …` when merged), `issued reason=… after=… waited=… attempts=… busy=… blit=…`, `verify issued …`, `panel busy→idle after …ms` (sampled every 50 ms while busy), `first full frame rendered in …ms`, `slow render: …`, one line per content update (`update partial|dynamic|finalize WxH+X+Y`, `damage … deferred to finalize (panel busy)`, `damage … held for pending present`), `pointer down|up x,y`, `key down …`, `waking InkView loop after updates … rc=…` once, and the rare `finalize fallback: full …`. Update rects in these lines are in content coordinates (below the panel, if any). `evt:` lines (including `PointerMove`) only with `INKVIEW_SLINT_TRACE_EVENTS`. Content updates must not log `request reason=App`. A dropped update shows as a full-screen `update …` followed by `panel busy→idle` within ~100 ms and nothing drawn until the next `pointer down`.
- **PB710 baselines** (`make release`, Oct 2026): first frame 300–500 ms after backend start; a full-screen `PartialUpdate` keeps the panel busy 550–650 ms (that is the floor for an answer or next card; going lower means smaller damage or `DynamicUpdate` for card changes, a ghosting/quality tradeoff to evaluate on-device); card jobs 10–30 ms, first deck entry ~200 ms (~135 ms of it `set_current_deck`); `answer_card` ~140 ms (FAT I/O; do not weaken SQLite durability to hide it); with the old Slint pin, fontdue first-use parse (vendored lazy patch): Ryo 48 ms, Adobe Ming 126 ms, Adobe Heiti 177 ms, Noto CJK 249 ms, and the UI family `Monospace` resolved to Roboto. These are not yet re-measured for Slint 1.18 (swash rasterization, fontconfig via dlopen).
- **Waveform probe on the PB710** (fw U710.6.11.2124, 1264×280 band, Nov 2026): `GetWaveformTimes` = `[11, 152, 329, 152, 117, 329, 235, 211, 152, 0, 0, 0, 0, 623, 329, 0]`. Busy time (`IsUpdateInProcess`): full/full-hq ~630 ms, soft 463, soft-hq 656, partial/partial-bw/partial-du4/dynamic/dynamic-bw ~443, partial-hq 610; `ex:` init/du/gc16/gc4/du4/glr16/gln16 ~440, a2 406, a2in 524, a2out 506, gl16 and gcc16 619. So `UpdateEx` passes the waveform bits through (gl16 ≈ partial-hq, a2 the fastest), but busy time does not follow `GetWaveformTimes` (du is 152 ms in the table, ~440 ms busy): ~440 ms looks like the floor for this band size, so faster waveforms would gain little latency here. Ghosting and quality differences still need a visual check.
- **Known minor issues:** rating taps produce empty damage; the backend now skips zero-area updates (an empty finalize still logs `update finalize 0x0+0+0`). The `[job N]` worker/delivery lines are always on (two per card job).
- KOReader reference: `ffi/framebuffer_pocketbook.lua` maps partial to `PartialUpdate`/`PartialUpdateHQ`, full to `FullUpdate`/`FullUpdateHQ`, fast to `DynamicUpdate`, and waits with `WaitForUpdateComplete`; `ui/uimanager.lua` promotes every 6th partial refresh to a full refresh (`FULL_REFRESH_COUNT`, default 6).
- Upstream (`simmsb/inkview-rs`, remote `upstream` in `../inkview-rs`) still has no full-refresh policy or `Show`/`Repaint` handling. To follow a newer upstream master, rebase `pbanki-upstream-master` and keep the Slint version in the fork and all three pbanki manifests identical (two Slint copies fail to compile at `set_platform`).
- **Profiling** is opt-in via the `profile` cargo feature (`pbanki-core`, forwarded by the `pbanki` and `pbanki-desktop` manifests; `make release-profile`, `cd crates/desktop && cargo run --features profile`). Without it, `profile_log!` and `ProfileTimer` (`crates/core/src/profile.rs`) compile to nothing and release binaries contain no `[profile]` strings. With it, `crates/core/src/study.rs` splits card loading into deck selection, queue, state descriptions, render, text processing, font choice, pagination, and answer write; `crates/core/src/fonts.rs` logs catalog, coverage, and registration timings; `app::start` logs startup; and `spawn_font_probe` logs the read time and size of each registered card font (Slint reads them fully at startup) and which font `Monospace` resolves to in Slint's shared collection, queried in Slint's order (named family, sans-serif, system-ui) (`[profile] font '…' … read=… bytes=…`, `[profile] UI family '…' resolves to …`), starting 10 s after launch at nice 19. Logs go to the eMMC-backed `pbanki.log`, so timings include logging overhead.

### Wi-Fi and sync

- `crates/pocketbook/src/network.rs` owns Wi-Fi. `ensure_connected()` checks `QueryNetwork() & NET_CONNECTED`; otherwise it powers the radio with `WiFiPower(1)` and uses the system `NetConnect(NULL)` dialog. `NetConnectSilent` is not used: on PB710 a cold radio can block for over a minute, and calling it off-thread can return `NET_ABORTED`. The dialog lets the user enable/select Wi-Fi without leaving the app. Failures map to actionable messages instead of opening the in-app sync settings.
- `disconnect_after_sync()` only disconnects connections the app established. It captures the active SSID with `NetInfo()` after connecting and skips `NetDisconnect()` if the current SSID changed, so a network the user switched to mid-sync is left connected.
- `pbanki_core::frontend` exposes `FrontendHooks { sync: SyncHooks, full_present }`, passed to `app::start`. `SyncHooks { before_sync, after_sync }` is invoked for every sync path (manual, full upload/download, startup auto-sync, sync-on-exit). `before_sync` runs on the UI thread and must be cheap and idempotent; it may show a platform prompt (for example Wi-Fi setup) but must not block indefinitely on its own. A failure sets a `SyncState` error and skips the sync. `after_sync` runs exactly once iff `before_sync` returned `Ok`, including when the sync fails or panics, and never runs after a pre-sync failure. Desktop passes no-op hooks.
- If Wi-Fi was already connected before sync, the app leaves it connected; only connections started by the app are disconnected afterward.
- InkView also exposes `NetConnect` (interactive dialog), `NetConnect2`, `NetConnectAsync`, `NetConnect3` (6.8+), `GetNetState`, `GetLastNetConnectionError`, `NetInfo`, `EnumWirelessNetworks`, and `NetMgrPing`. `EVT_NET_CONNECTED`/`EVT_NET_DISCONNECTED` are not surfaced by `inkview::Event`, so status would need polling.

## Lint rules (ast-grep)

- `sgconfig.yml` + `lint/rules/*.yml` (one rule per file, id prefix `pbanki-`) + `lint/rule-tests/*-test.yml` (`valid`/`invalid` snippets). The rules encode invariants from this file that clippy cannot check: no repeating Slint timers, no `wait_for_update_complete`/`WaitForUpdateComplete`, no `NetConnectSilent`, no `SLINT_FONT_PATH`/`SLINT_DEFAULT_FONT`, `SyncState` built through its constructors outside `frontend/models.rs`, a hint for collection borrows in `ui.on_*` closures without a `busy` check, and in Slint: every CheckBox sets `font-size`, no `focus()` in `init`, no `states`/`transitions`/`animate`/`.pressed`/`.has-hover` in `plain_button.slint` and `rating_button.slint`.
- `make lint` builds the Slint parser if needed (`make lint-parsers`: clones `slint-ui/tree-sitter-slint` at the commit pinned in the Makefile into `target/ast-grep/` and builds `slint.so` with the tree-sitter CLI), runs both clippy invocations, `ast-grep test`, and `ast-grep scan`. The scan exits 1 on `error` rules; `warning`/`hint` rules only report. Requirements: `cargo install ast-grep --locked` (0.51; `~/.cargo/bin` need not be on `PATH`, the Makefile falls back to it) and `npm i -g tree-sitter-cli`.
- Slint is a custom language: ast-grep only loads the native parser with `--custom-languages allow` (the Makefile passes it). Without it, Slint rules are skipped, not failed.
- Workflow for agents: use `ast-grep run -l rust -p '<pattern>'` (or `-l slint` with `--custom-languages allow`) for structural search and codemods (`-r '<rewrite>' -i` to review each change); check how a pattern parses with `--debug-query=cst` first (Slint fragments must sit inside a `component X { … }`; bare elements parse as `ERROR`). For a new rule, add its tests, run `ast-grep test --custom-languages allow --skip-snapshot-tests`, and confirm the scan stays clean. Prefer `kind` + `regex` over a pattern for paths (`TimerMode::Repeated` as a pattern misses `slint::TimerMode::Repeated`). Suppress a deliberate exception with `// ast-grep-ignore: <rule-id>` and a reason.
- Do not run `ast-grep scan` from a directory with another project's `sgconfig.yml` (it is picked up from the working directory). The `joshuadavidthomas/ast-grep-rules` Rust pack was evaluated and not adopted (its hits here were deliberate designs: public data fields, the startup panic, bool parameters).

## Gotchas

- `anki`/`anki_proto` come from `ankitects/anki` `branch = "main"` (git dep, unpinned); `slint`/`slint-build` are `1.18.1` from crates.io. The single workspace `Cargo.lock` pins the anki revision for both frontends; do not `cargo update` it together with other changes.
- **Slint 1.18 fonts.** Slint 1.16+ rasterizes glyphs with swash (lazy per glyph) instead of fontdue, so the old vendored fontdue patch (eager outlining took 5.5 s for Ryo Gothic and 16 s for Adobe Ming on the PB710) was removed; if a future Slint brings fontdue back, re-check first-render time. fontique 0.11 links fontconfig on Linux; the root manifest enables `fontique/fontconfig-dlopen` so the armv7 cross build needs no fontconfig sysroot, and without `libfontconfig.so.1` on the device system fonts are skipped (registered card fonts still work, and become the UI fallback). The PB710 has it: `Monospace` resolves to Roboto.
- **Glyph embedding.** `crates/core/build.rs` uses `EmbedForSoftwareRenderer`, which pre-rasterizes every literal font size in the UI (plus the SVG icons, which need it: runtime SVG decoding is not enabled). A constant `0px` size, such as an unset std-widgets `CheckBox` `font-size`, is rasterized at the font's design size: 380 MB of generated code and an 80 MB binary. `crates/core/ui/screens/settings.slint` therefore sets every CheckBox to `12px` (Slint's default); the blowup only appears once no CheckBox overrides the size (with Slint 1.18 one unset CheckBox among set ones still built at 2.8 MB, all unset produced 264 MB), so a single missing size is a latent bug. `pbanki-checkbox-font-size` enforces it. After UI changes, check that `target/*/build/pbanki-core-*/out/main.rs` stays around 3 MB and has no `pixel_size : 0`. The embedded bitmap font is whatever default sans the build host has (Noto Sans here), with only ASCII plus characters from `.slint` literals. With `systemfonts`, Slint uses a bitmap font only when a text's requested family matches its name exactly, or as the last fallback when the requested family resolves to nothing or no family is requested. `MainWindow` therefore sets `default-font-family: Constants.font_family_standard`, so std-widgets labels (CheckBox, Button) also use the runtime UI font and render any translated characters; this replaced a `dummy` string property that only padded the bitmap font with Latin-1 glyphs.
- Root `Cargo.toml` uses the fork's git branch `pbanki-device-panel` for InkView. Keep that branch pushed; pin a specific rev if reproducibility matters. Fork development still uses the local checkout `../inkview-rs`. The user permits committing and pushing InkView changes to the fork's pbanki branches as part of normal work.
- Slint's version and base software-renderer features are set once in the root `[workspace.dependencies]`; members only add features (`unstable-fontique-011` in core, `backend-winit` in desktop). `crates/core/build.rs` embeds resources `EmbedForSoftwareRenderer`.
- PocketBook fonts: USB/mass-storage view shows `/system/fonts` and `/system/adobe/fonts`, but on-device the runtime paths are `/mnt/ext1/system/fonts` and `/mnt/ext1/system/adobe/fonts`. PB700 images use `/fonts` and `/adobefonts` (not `/ebrmain/fonts`). `/mnt/ext1/system/adobe/fonts/RyoGothicPlusN-Medium.otf` (2.3 MB, typographic family `Ryo Gothic PlusN`) covers Japanese and is the card default; `/mnt/ext1/system/fonts/NotoSansCJK-Regular.ttc` is a 19 MB CFF collection, and `fireflysung.ttf` lacks `両`. `crates/core/src/fonts.rs` builds a catalog from `Config.general.font_dirs` (reading only each file's sfnt/TTC table directory and `name` table, not the whole file), registers the primary/fallback files with Slint via `crates/core/src/fonts.rs::register_catalog_fonts` (called by `app::start` before `MainWindow::new`; the files are memory-mapped into Slint's shared fontique collection via `slint::fontique_011::shared_collection()` (feature `unstable-fontique-011` in `crates/core/Cargo.toml`; needs the Slint platform, so call it after `set_platform`), ordered by configured family and put first in the Hira/Kana/Hani/Hang fallback chains. Do not use `SLINT_FONT_PATH`/`SLINT_DEFAULT_FONT`: in Slint 1.18 they make the registered fonts the generic sans-serif chain, and the UI family `Monospace` (not a real family, so it falls back to sans-serif) then rendered in Ryo Gothic instead of Roboto), and checks card text against each font's cmap. `next_card` picks the first font that covers the whole card; if none does, it replaces the missing glyphs with `?` instead of rendering missing glyphs. Card text uses `Config.general.card_font` plus `card_fallback_fonts`; the UI stays `Monospace` (Roboto on the PB710).
- `Config` stores its loaded path in the serde-skipped `path` field; `save()` writes there. `[ankiweb].endpoint` is blank for AnkiWeb, and `sync_media` defaults to true. `[general]` has `card_font` (default `Ryo Gothic PlusN`), `card_fallback_fonts` (`Adobe Ming Std`, `Adobe Heiti Std`, `Noto Sans CJK JP`), and `font_dirs` (PB710 runtime, USB, and PB700 paths). `load_or_create` adds any missing font keys to an existing config and saves it; the generated template contains all three.
- **Card loads run off the UI thread.** `next_card`/`rate_card` in `crates/core/src/study.rs` are collection-only functions returning `LoadedCard`; `crates/core/src/frontend/card_jobs.rs` takes the collection out of `LearnSession`, runs the job on a `std::thread`, and puts it back when the result arrives. While a job or sync is active, `LearnSession.busy` is true and `MainWindow.busy` mirrors it, so Home and deck-selection navigation are ignored until the collection is available again; `LearnScreen.busy` disables Show Answer, the rating buttons, and study keys so taps aimed at the next card are not swallowed by the previous card's controls. The UI also shows a loading state (`MainWindow.loading` / `loading_message`). Do not touch the collection from UI callbacks without checking `busy`.
- Deck loads show the loading screen only if the job is still running after 200 ms (`Loading::Transition(DECK_LOADING_DELAY)`), so fast loads present the card with a single full present instead of loading screen + card. The deck list stays visible until then: `MainWindow.learning` is set from Rust (loading timer, `finish_job`, or the collection-unavailable error) rather than in `ui/main.slint`, so `LearnScreen` never renders the previous session's card. Because `LearnScreen` is then created while the window layout is being evaluated, it takes key focus from a one-shot `Timer`, not `init => { self.focus(); }`, which re-entered the geometry binding and aborted with Slint's "Recursion detected"; do not move focus calls back into `init` of conditionally created screens; `on_open_settings` ignores taps while busy because the gear stays reachable during that window. Rating loads defer it by 300 ms (`Loading::Deferred(RATING_LOADING_DELAY)`) so the `RatingButton` that received the click is not removed inside its own click callback, and the rating handlers do not change `show_answer`; the answer stays visible until the deferred loading overlay or the next card (`changed card` resets it). Finishing a job bumps `job_seq` so its deferred overlay timer cannot fire during a later sync or job.
- Background card jobs deliver results with `slint::invoke_from_event_loop` (both backends implement the event loop proxy): `spawn_card_job` stores the single in-flight job in the thread-local `PENDING_JOB`, and the worker's `DeliverOnDrop` guard schedules `deliver_job`, also when the job panics (its sender is dropped first, so delivery sees the result or a disconnected channel). Card-job loading and result transitions call `request_redraw()` explicitly so the backend presents their damage without waiting for further input. Slint timers only fire because the backend drives `duration_until_next_timer_update`. The proxy also makes it possible to move the blocking sync off the UI thread later.
- **Re-test redraws after InkView/Slint upgrades.** On PB710, implicit property invalidation alone could leave a loading screen or already-delivered card invisible until another touch, even when the worker finished in milliseconds. The explicit `request_redraw()` calls in `spawn_card_job`, its deferred loading timer, and `finish_job` are intentional. Before removing them after an upgrade, verify cold-launch deck selection, loading-to-card transitions, rating, and Home/re-entry without any extra touch. Device logs (`pbanki/logs/pbanki.log`, see the e-ink log notes) show whether a stale screen was never rendered, never issued, or dropped by the panel.
- `set_current_deck` (~135 ms on the PB710) is only called when the selected deck actually changes (`LearnSession.current_deck_id`), avoiding a transaction per card. The cache is cleared by `session::reset_session_memory` after every sync (a merge can pull another device's `curDeck` or delete the deck) and after a failed card load; deck entry logs `[deck <id>] entering, set_deck=<bool>`. A failed `answer_card` returns an error card instead of loading the unchanged queue head (test in `study.rs`). `start_time` is recorded when the card is displayed, so `milliseconds_taken` excludes load/render time.
- Sync now supports normal merge, full upload/download, and media sync in `crates/core/src/sync/`. Full sync and card loads both temporarily take the collection out of `LearnSession.collection` (an `Option`) and reopen/restore it; they share `LearnSession.busy`. Sync is still blocking on the UI thread; progress/abort is not implemented (the unused `SyncStatus` progress plumbing was removed; add progress back together with off-thread sync).
- Anki queue builds are much slower in the dev profile. Measure card-load latency with `make release`; `make` (dev) and `scripts/sdk-emulator/build.sh` use the dev profile (`PROFILE_CARGO=release` for the emulator).
- `sync_on_exit` means after leaving a study session (LearnScreen home), not on application exit.
- Sync settings live in `crates/core/ui/screens/settings.slint`; the home gear opens it and the reload icon triggers sync. Shared wiring lives in `crates/core/src/frontend/`; PocketBook adds the native InkView keyboard (`crates/pocketbook/src/keyboard.rs`, wired in `main.rs` by `EditField`) and desktop uses normal `LineEdit` input. The keyboard result is delivered with `slint::invoke_from_event_loop` (the callback runs on the InkView thread); a cancelled keyboard (NULL text) keeps the field unchanged. The buffer is 512 bytes including the NUL; longer initial values are truncated on a character boundary.
- `init_session` calls `with_desktop_media_paths()` so `collection.media/` and `collection.mdb` exist. Do not remove this or media sync will fail.
- On startup, `init_session` imports any unimported `*.apkg` in the collection directory (including scheduling/media) and renames it to `*.apkg.imported`. This is how users install decks on-device; see `import_pending_packages()` in `crates/core/src/session.rs`.
- `crates/core/src/session.rs` suspends "Image Occlusion Enhanced" cards at session init.
- **SDK emulator** (`scripts/sdk-emulator/`): the PC InkView reads everything relative to `./system` (working dir `target/sdk-emulator/<sdk>/work`); `system/mnt/ext1` is also mounted as `/mnt/ext1`, so device paths work unchanged. The window size comes from the emulator's Display Mode (`emu_resmode` in `system/config/global.cfg`, set by `run.sh` from `RESMODE`; enum order `ACDisplayMode…`: 2 = 758×1024, 9 = 1448×1072, 12 = 1404×1872, 16 = 1264×1680, 17 = 1264×1680 shown at 1/2), not from the hwconfig profile (`PROFILE`, copied to `system/config/hwconfig`, sets device ID/platform/EPDC). The emulator always reports 300 dpi, so the 1030 profile (227 dpi) logs the DPI-mismatch warning. Checked on 6.10 and 6.11 (Nov 2026): deck import, deck entry, answer, rating, Home, Settings, native keyboard (`OpenKeyboardEx`), and sync login to the dev server with `EMU_NET=host` all work; `QueryNetwork` reports connected, so no network override is needed. Not emulated: e-ink timing (`IsUpdateInProcess` never reports busy, so presenter waits and the dynamic path are not exercised; use `eink-sim` or the device), the system tray, scanner/other tasks. GTK ignores synthetic X events: drive it with XTEST (`xdotool mousemove --window W x y; xdotool click 1`, window coordinates are half the framebuffer's in the compressed view). The bundled deck `JLPT_N2_Grammar.apkg` is local-only (`.git/info/exclude`).
- The SDK emulator runs the x86-64 binary directly, so it does not exercise the release launcher (`scripts/pocketbook/pbanki.app`) or ARM codegen. Launcher changes need a device check.
- **eink-sim** (`crates/desktop/src/eink_sim.rs`): `SimScreen` implements `inkview_slint::EinkScreen` (BB8 framebuffer + a queue of pending updates applied to the visible frame after per-kind delays, quantized to 16/4/2 grays, full updates flash black for the first half). minifb polls input once per frame, so scripted clicks must hold the button (`xdotool mousedown 1; sleep 0.08; xdotool mouseup 1`).
